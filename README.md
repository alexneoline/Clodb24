# SKU-синхронизация товаров сделок для Битрикс24

Локальное приложение для портала **neoline.bitrix24.ru**:

1. Подписывается на событие `OnCrmDealUpdate` (`event.bind` при установке).
2. При изменении сделки получает её позиции через `crm.deal.productrows.get`.
3. Из названия каждой позиции извлекает артикул вида `[SKU-123...]`.
4. Ищет товар в каталоге через `catalog.product.list` по полю с артикулом.
5. Записывает найденный `PRODUCT_ID` в позицию через `crm.deal.productrows.set`.
   Цена, количество, скидки, налоги и название позиции сохраняются.

`crm.deal.productrows.set` снова вызывает `OnCrmDealUpdate`, поэтому приложение
записывает позиции только тогда, когда что-то действительно изменилось, — зацикливания нет.
События по одной сделке обрабатываются последовательно.

Зависимостей нет, нужен только Node.js ≥ 18.

## Запуск

```bash
cp .env.example .env      # заполнить значения, см. ниже
npm start                 # сервер на PORT (по умолчанию 3000)
npm test                  # тесты
```

Серверу нужен публичный HTTPS-адрес, например `cloudflared tunnel --url http://localhost:3000`
или `ngrok http 3000`. Этот адрес указывается в `PUBLIC_URL`.

## Регистрация локального приложения в Б24

1. Откройте в портале **Разработчикам → Другое → Локальное приложение**.
2. Тип: *серверное*. Путь обработчика — `https://<PUBLIC_URL>/handler`,
   путь для первоначальной установки — `https://<PUBLIC_URL>/install`.
3. Права: `crm`, `catalog`.
4. Сохраните приложение, затем скопируйте `client_id` и `client_secret` в `.env`
   (`B24_CLIENT_ID`, `B24_CLIENT_SECRET`).
5. Откройте приложение в портале. Во время установки токены сохраняются в `data/auth.json`,
   и создаётся подписка на `ONCRMDEALUPDATE` → `PUBLIC_URL/handler`.

Если `PUBLIC_URL` изменился, переподпишитесь командой `npm run bind`.
Проверить одну сделку вручную: `npm run sync -- <ID сделки>`.

## Настройка каталога

| Переменная | Назначение |
|---|---|
| `CATALOG_IBLOCK_IDS` | ID инфоблока каталога (несколько — через запятую). Его показывает `catalog.catalog.list`. |
| `SKU_FIELD` | Поле с артикулом: `property<ID>` для свойства (например, `ARTNUMBER`), `xmlId` или `code`. |
| `SKU_REGEX` | Шаблон артикула в названии; группа 1 — искомое значение. По умолчанию `\[(SKU-[A-Za-z0-9._/-]+)\]`. |

Из названия `Видеорегистратор Neoline [SKU-12345]` приложение ищет в каталоге значение
`SKU-12345` — именно в таком виде артикул должен храниться в поле `SKU_FIELD`.

## Способы вызова REST (`B24_TRANSPORT`)

- `oauth` (по умолчанию) — токены локального приложения, обновляются автоматически
  через `oauth.bitrix.info`. Только в этом режиме работает `event.bind`.
- `webhook` — входящий вебхук (`B24_WEBHOOK_URL`). Подписку на событие в этом режиме
  нужно создать вручную: исходящий вебхук на `OnCrmDealUpdate` с адресом `PUBLIC_URL/handler`,
  а его «токен приложения» записать в `B24_APP_TOKEN`.
- `vibe` — шлюз Вайбкод (`VIBE_API_URL`, `VIBE_API_KEY`, заголовок `VIBE_AUTH_HEADER`).
  URL запроса строится как `VIBE_API_URL/<метод>`. **Этот формат не сверен с документацией
  Вайбкода**, при необходимости поправьте `endpoint()` в `src/b24client.js`.

## Безопасность

Входящие события проверяются по `auth[application_token]`. Значение берётся из `B24_APP_TOKEN`
или сохраняется при `ONAPPINSTALL` либо первом полученном событии. Ключи и токены хранятся
только в `.env` и `data/` — обе папки исключены из git.
